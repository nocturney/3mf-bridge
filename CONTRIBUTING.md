# Contributing to SliceBridge

Thanks for helping build a more open workflow across printer ecosystems. The project is **pre-release**: check existing issues and PRs before starting new work.

1. **Discuss the scope:** open or comment on an issue describing the problem and supported printer/slicer combinations. Do not advertise unverified universal printer support.
2. **Use a separate branch and PR.** Keep changes focused; identify source and test conditions. Do not merge your own PR without the project's QA process.
3. **Provide test evidence:** automated checks, OS and slicer versions, nozzle and material configuration, screenshots or synthetic sample projects where useful. State explicitly when a physical print or slicer import has **not** been tested.
4. **Respect upstream software and models:** do not commit or redistribute vendor profiles, proprietary slicer resources, customer 3MF files or assets without demonstrated redistribution rights. Prefer loading already installed resources, where legally and technically appropriate.
5. **Keep security and privacy in mind:** never commit tokens, customer files or private paths. Follow [SECURITY.md](SECURITY.md) for vulnerability reports.
6. **Document user-visible changes:** update relevant release notes, support documentation and translated text.

Project-owned code contributions are intended to be accepted under **[GPL-3.0-only](LICENSE)**, without a copyright assignment or CLA. By submitting, contributors represent that they have the right to grant the necessary licenses. Identify source and original licenses for reused code or assets. Contributors keep their own copyright; GPL-3.0-only applies where they can grant it.

Code submissions remain subject to third-party clearance review; do not assume upstream files become freely redistributable because their source repositories are public. Consult [LICENSING.md](LICENSING.md) and [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).

For qualified testers, use the [limited beta guide](BETA_TESTING.md) and structured beta feedback form. Do not treat experimental pre-release artifacts as stable builds.

Useful links: [roadmap / printer catalogue #7](https://github.com/nocturney/slicebridge/issues/7) · [support](SUPPORT.md) · [release checklist](DISTRIBUTION_CHECKLIST.md).
